# Задачка дня на истории — дизайн

Дата: 2026-11-24. Идея №2 из `docs/ideas.md`.

## Зачем

Раз в день игрок за полминуты читает реальный кусок графика из прошлого и решает:
лонг, шорт или пропустить. Потом видит, что было дальше, и короткий разбор со
ссылками на уроки. Цели две: научить читать сетап (тренд + RSI) и дать повод
заходить каждый день. Портфель не рискует.

## Цели, не-цели, анти-цели

- Цель: ответ засчитывается **по сетапу**, а не по исходу цены. Исход показываем
  отдельно и честно.
- Цель: ноль ручной работы — задачка собирается сама из свечей в БД.
- Не-цели (позже, отдельными задачами): серия дней (streak), пост задачки в канал,
  уведомление «новая задачка», таймер на 30 секунд, архив прошлых задачек.
- Анти-цель: XP за угаданное движение цены. Если игрок получает награду за удачу,
  фича учит обратному (см. идею «удача, а не скилл»).
- Анти-цель: подбирать только моменты, где сетап сработал. Задачки не фильтруются
  по исходу; примерно в трети случаев игрок увидит «сетап верный, цена ушла против».

## Подходы (выбран 1)

1. **Правила на наших индикаторах** — выбран. Те же EMA fast/slow и RSI, что в
   уроках 06/07, подсказках `order_tips` и разборе «Почему ИИ так сходил».
   Автоматически, согласовано с уроками. Минус: правило простое.
2. Правильный ответ = решение ИИ-персонажа. Отвергнут: модели слабые на отложенных
   данных, учили бы повторять за слабой моделью.
3. Ручная подборка через админку. Отвергнут: некому размечать каждый день.

## Правило правильного ответа

На момент `ts` (закрытие свечи) считаем `indicators_at(db, symbol, ts)`:

- `gap = |ema_fast - ema_slow| / ema_slow`. Если `gap < PUZZLE_MIN_EMA_GAP` — тренда
  нет, момент **не годится** (не кандидат).
- `rsi is None` — не кандидат.
- Тренд up: RSI > 70 → ответ `skip`; иначе → `long`.
- Тренд down: RSI < 30 → ответ `skip`; иначе → `short`.

`PUZZLE_MIN_EMA_GAP` — константа в `app/game/config.py`, стартовое значение 0.002
(0.2%). Решение исполнителя: подобрать так, чтобы на 30 днях BTC/ETH/SOL кандидатов
было с запасом, и при этом линии EMA на графике заметно расходились.

## Как выбирается задачка

- Одна задачка на всех на UTC-день (`day_key`, как в `app/game`).
- Создаётся **лениво** при первом запросе дня, без планировщика. Гонку двух
  запросов закрывает первичный ключ `day` + savepoint с `IntegrityError`
  (как в `complete_lesson`).
- `ts` везде — время **закрытия** свечи. Последняя свеча до момента — та, что
  открылась в `ts − 5m` (ровно её видит `indicators_at`). График, EMA, RSI и исход
  отсчитываются от неё; свечи в БД хранятся по времени открытия.
- Детерминированный `random.Random(day)`: символ из `STARTER_SYMBOLS` (их видят все
  уровни), затем до N попыток случайного `ts` на границе 5m-свечи в окне
  `[D − 29 дней, D − 2 часа]`, где `D` — начало текущего UTC-дня (не `now`, иначе
  один и тот же сид даёт разные моменты в разное время дня). Первый кандидат по правилу выше — задачка.
  Нижняя граница с запасом, чтобы до `ts` было ≥100 свечей истории; верхняя —
  чтобы после `ts` уже были свечи для раскрытия.
- Не нашли кандидата (мало свечей, например на свежей БД) → задачки сегодня нет,
  API отдаёт `null`, карточка в Mini App скрыта. Повторная попытка — при следующем
  запросе (ничего не сохраняем).
- В строке задачки храним `day, symbol, ts, answer, rsi, ema_fast, ema_slow` —
  снимок на момент создания, чтобы разбор не менялся, если свечи дозальются позже.

## Что видит игрок

Вкладка «Учёба» (`learnScreen`), карточка сверху над уроками:

```
┌ Задачка дня ──────────────────────┐
│ SOL/USDT · 5m          RSI 58     │
│ [график: 60 свечей + EMA fast/slow]│
│  [ Лонг ]  [ Шорт ]  [ Пропустить ]│
└───────────────────────────────────┘
```

- Дата и время на оси графика скрыты. Символ показан. API при этом отдаёт настоящие
  метки времени — это сознательно: правильный ответ зависит только от данных до `ts`,
  так что подсмотренный исход не даёт преимущества.
- График: 60 свечей до `ts` включительно, две линии EMA, число RSI. Рисуется тем же
  lightweight-charts, что и на торговом экране.
- Один ответ на игрока в день, без переигровки. Таймера нет — «30 секунд» это формат.

После ответа (и при повторном открытии в тот же день) карточка раскрыта:

```
│ ✅ Верно: тренд вверх, RSI 58 не перегрет → лонг   (+30 XP) │
│ [график: те же 60 свечей + следующие 12, граница отмечена]  │
│ Через час цена: +0.8%                                      │
│ Тренд — урок 06 ›   RSI — урок 07 ›                         │
│ Ответили так же: 63% · верно ответили: 55%                  │
```

- Неверный ответ: «Сетап говорил: лонг» + тот же разбор, 0 XP.
- Исход: изменение close через 12 свечей (1 час) относительно close в `ts`. Если
  исход против правильного ответа — отдельная строка: «Сетап был верный, но цена
  ушла против. Так бывает — важна дисциплина, а не одна сделка.»
  Для `skip` исход просто показываем без оценки.
- Разбор — шаги `trend` и `rsi_overbought | rsi_oversold | rsi_neutral` с уроками
  из `WHY_LESSONS`. Тексты шагов в `static/miniapp/i18n.json`, RU/EN.
- Проценты сообщества: доля ответивших тем же вариантом и доля верных по
  `puzzle_answers` за этот день.

## Данные

Миграция `0009_daily_puzzle`:

- `daily_puzzles`: `day` (str, PK), `symbol`, `ts` (bigint ms), `answer`
  (`long|short|skip`), `rsi`, `ema_fast`, `ema_slow`, `created_at`.
- `puzzle_answers`: `id`, `player_id` (FK players), `day` (FK daily_puzzles),
  `choice`, `correct` (bool), `answered_at`; уникальность `(player_id, day)`.

XP: `XP_PER_PUZZLE = 30` в config (между сделкой 10 и уроком 50), только за верный
ответ, через `award_xp`. Событие `log_event(..., "puzzle_done", ...)` для аналитики.

## API (`app/api/game_routes.py`)

- `GET /puzzle` → `null` или
  `{day, symbol, rsi, candles[60], ema_fast[60], ema_slow[60], answered: null | result}`.
  До ответа **не** отдаём `answer` и свечи после `ts`.
- `POST /puzzle/answer {choice}` → `result`:
  `{choice, answer, correct, xp, after[12], outcome_pct, steps[{code, lesson_id}], same_pct, correct_pct}`.
  Повторный ответ → ошибка `GameError` с кодом `puzzle_answered` (409), как прочие
  игровые ошибки; гонку закрывает уникальный индекс + savepoint.
- Свечи — тот же формат, что у `GET /candles` (`time` в секундах). EMA считается
  `IndicatorService.calculate_indicators` по 100 свечам до `ts`, отдаём хвост 60.

Логика — в новом модуле `app/game/puzzle.py`; роуты только вызывают его.

## Тесты

- Правило ответа: up/down × RSI нейтральный/крайний, нет тренда, `rsi None`.
- Выбор: детерминирован для дня; на пустой БД → `None`; повторный запрос дня
  возвращает ту же строку.
- Ответ: XP только за верный, повтор → `puzzle_answered`, до ответа в `GET /puzzle`
  нет `answer`/`after`.
- Проценты сообщества на 2–3 игроках.

## Остаётся на исполнителя

- Число попыток поиска кандидата N, точное значение `PUZZLE_MIN_EMA_GAP`.
- Вёрстка карточки и маркер границы `ts` на графике (вертикальная линия или
  маркер серии — что проще в lightweight-charts 4.2).
- Формулировки текстов RU/EN.
